Panduan untuk teman

Mulai dengan satu kandidat. Setelah instalasi, pengisian dan pengambilan data dilakukan melalui halaman aplikasi ini.

Manusia memilih link dan memverifikasi drip marketing. API mengambil metadata dan komentar setelah tombol dijalankan. Angka revenue tetap diisi manual dari satu seri sumber.

1. Instalasi dan menyalakan aplikasi

Pada Windows, pasang Python 3.12. Ekstrak ZIP proyek dan buka PowerShell pada folder yang berisi setup_project.py dan run.py.

python setup_project.py
python run.py

Tunggu pesan Instalasi selesai sebelum menjalankan perintah kedua. Buka alamat yang ditampilkan di terminal, biasanya http://127.0.0.1:5000. Biarkan terminal berjalan. Besok cukup jalankan python run.py atau klik ganda run.bat.

Jika versi lama melaporkan No module named pip, jalankan perintah berikut, lalu ulangi instalasi:

.\.venv\Scripts\python.exe -m ensurepip --upgrade

No module named flask berarti instalasi dependensi belum selesai. Ulangi setup; tidak perlu menghapus data.

2. Isi Pengaturan & API

  1. Buka Pengaturan & API. Masukkan API key YouTube Data API v3 pada kolom password. Key hanya disimpan dalam memori server dan perlu diisi kembali setelah server berhenti.
  2. Periksa dasar penggunaan proyek. Isi Tanggal tinjauan kebijakan dengan tanggal peninjauan yang sebenarnya.
  3. Pada Referensi dasar penggunaan proyek, catat sumber/URL atau dokumen yang benar-benar ditinjau, operasi yang dicakup, dan pembatasannya. Jika belum tahu isinya, minta penanggung jawab penelitian meninjaunya; jangan mengarang persetujuan.
  4. Isi Masa simpan data / retensi (hari) dengan bilangan bulat 1–30. Misalnya 30 berarti paket disimpan paling lama 30 hari sejak dibuat. Ini berbeda dari jendela komentar 72 jam.
  5. Untuk langkah metadata nyata, centang Baca metadata YouTube dan nonaktifkan Offline / dry-run setelah catatan penggunaan lengkap. Operasi lain diaktifkan sesuai langkah dan dasar penggunaan yang tersedia.
  6. Klik Simpan pengaturan, lalu ulangi tombol yang sebelumnya gagal.

Pesan lama Document the requested data-use scope and policy review; packages require retention of 1-30 days berarti ada pengaturan yang belum lengkap. Pesan itu tidak menunjukkan kolom mana yang bermasalah dan tidak membuktikan API key salah. Versi ini menampilkan butir yang perlu dilengkapi.

Mengisi form mendokumentasikan keputusan proyek, bukan memberi izin dari YouTube. Jika dasar untuk suatu operasi belum tersedia, kerjakan kandidat/data manual dalam mode offline.

3. Masukkan satu link dan ambil metadata

  1. Buka Kandidat & verifikasi. Masukkan satu link https://youtube.com/shorts/VIDEO_ID, isi nama karakter bila diketahui, lalu klik Tambah sebagai pending.
  2. Jika link sudah terdaftar, buka baris yang ada melalui Buka / edit.
  3. Klik Ambil / refresh metadata. Tunggu proses selesai, klik Lihat kandidat, lalu buka kembali detail kandidat.
  4. Judul, channel ID, kecocokan kanal resmi, dan waktu publikasi UTC kini berasal dari API. API tidak menentukan apakah video benar drip marketing.

4. Lengkapi verifikasi manusia

Tonton Short dan periksa bukti pengumuman awal. Isi nama karakter, URL sumber pengumuman awal, waktu pengumuman awal UTC, serta catatan bukti/pemeriksa. Waktu awal lintas platform terpisah dari waktu publikasi Short.

Format waktu: YYYY-MM-DDTHH:MM:SSZ. Huruf Z berarti UTC; untuk WIB kurangi 7 jam, untuk WITA 8 jam, untuk WIT 9 jam, dan perhatikan pergantian tanggal. Jangan menebak waktu jika bukti tidak cukup.

  • pending: masih menunggu bukti/pemeriksaan.
  • included: bukti lengkap, metadata kanal resmi, publikasi Januari–September 2026, dan jenis konten Short pengumuman awal, sudah diperiksa.
  • excluded: tidak memenuhi kriteria; isi alasan, misalnya ternyata teaser/demo.
  • no_matching_short: setelah penelusuran, tidak ditemukan Short yang sesuai; isi alasan. Kandidat seperti ini dapat dicatat dengan nama dan link kosong.

Klik Simpan verifikasi. Pada Cakupan bulanan, catat penelusuran tiap bulan. Pilih completed hanya setelah pencarian selesai dan waktu serta buktinya dicatat.

5. Ambil komentar otomatis

  1. Pastikan ada kandidat included dan jendela 72 jam setelah publikasi sudah selesai.
  2. Di Pengaturan, aktifkan Kumpulkan komentar utama jika tercakup dasar penggunaan, lalu simpan.
  3. Buka Komentar & NLP. Untuk percobaan satu kandidat, pilih Semua event included (boleh untuk uji kecil). Pilot temporal memerlukan minimal enam event.
  4. Klik Mulai pengumpulan. Tunggu hingga selesai. Buka Lihat dataset, lalu Buka pada dataset yang baru dibuat.

Aplikasi mengambil seluruh halaman komentar utama yang masih dapat diakses, menghapus duplikat ID, dan menandai kelayakan berdasarkan waktu. Maksimum 100 komentar per halaman API, bukan 100 komentar total. Video lama bisa memerlukan banyak halaman dan kuota.

Periksa bahwa pagination lengkap. Jika terputus, perbaiki masalah dan buat pengambilan baru. Setiap klik pengumpulan membuat dataset baru; tidak ada pengambilan terjadwal atau kelanjutan otomatis.

6. Sentimen, evaluasi, revenue, dan eksperimen

  1. Aktifkan operasi Analisis sentimen dan evaluasi data nyata jika dasarnya tersedia. Pada dataset lengkap, klik 1. Jalankan NLP lokal. Model pertama kali mengunduh sekitar 500 MB; berikutnya menggunakan cache lokal.
  2. Buka 2. Anotasi manual → buat sampel → isi label manusia → simpan setiap halaman. Jika dua anotator tersedia, kerjakan secara independen.
  3. Klik 3. Evaluasi model. Prediksi model bukan jawaban benar; evaluasi membutuhkan label manusia.
  4. Buka Revenue. Isi form per bulan atau impor CSV dari satu seri estimasi mobile yang sudah diperiksa. Jangan mengarang angka dan tanggal ketersediaan.
  5. Aktifkan operasi Gabungkan agregat dengan revenue eksternal jika tercakup dasar penggunaan. Kembali ke dataset dan klik 4. Analisis revenue t+1.
  6. 5. Forecast eksperimen boleh berstatus blocked karena data belum cukup. Satu kandidat hanya menguji alur; tidak cukup untuk korelasi atau prediksi yang dapat diandalkan.

Sentimen dikelompokkan menurut bulan ketika jendela 72 jam selesai, lalu dipasangkan dengan revenue bulan berikutnya. Hubungan ini eksploratif; tidak membuktikan sebab-akibat atau mewakili seluruh pemain/pembayar.

7. Menutup aplikasi dan melaporkan hasil

Hentikan server dengan Ctrl+C ketika tidak ada proses berjalan. Data tersimpan di data/workbench/; key form tidak ikut tersimpan. Data yang kedaluwarsa dapat dihapus ketika aplikasi aktif. Cadangan/ekspor mengikuti retensi yang sama dan perlu dikelola sendiri.

Kirim laporan berisi versi/branch, langkah yang dicoba, hasil, dan pesan error. Jangan sertakan API key atau komentar mentah.
